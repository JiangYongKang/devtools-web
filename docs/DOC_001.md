
### 文档背景

1. 本任务对应 `features/TASK_001.md` 与 `features/FEATURE.md` 任务 001，目标是在站内提供 Unix 时间戳与人类可读日期时间的双向互转工具页。
2. 时间换算的权威结果由后端 REST 接口统一产生，前端仅负责参数组织、请求构造、加载与错误呈现、结果展示与复制。
3. 前端不得自行实现与后端规则冲突的核心换算作为界面「权威结果」；若存在本地推算，仅可作为辅助对照，且不替代接口返回。

### 文档目标

1. 记录时间戳转换工具的实现结构（API 封装、页面组件、路由接入方式），便于后续维护与联调。
2. 说明环境变量与 CORS 策略、可运行的验证步骤、已验证的浏览器与运行条件。
3. 明确已知限制与后续可扩展点（如批量转换、本地对照预览）。

### 实现说明

1. **模块结构**

   - `src/services/timestampApi.js`：统一 HTTP 出口与时间戳相关 API 封装。
     - 封装 `toDateTime()` 与 `toTimestamp()` 两个核心请求方法。
     - 提供 `ApiError` 类型用于统一识别业务错误（含 `errorCode` 与 `errorMessage`）。
     - 响应解析统一处理：即使 HTTP 400，只要返回约定包络，也按 `success` 字段解析失败。
     - 导出时区、粒度、格式模式常量，供页面直接复用。

   - `src/components/TimestampConverter.jsx`：时间戳转换工具页面组件。
     - 支持「时间戳 → 日期时间」与「日期时间 → 时间戳」两条转换路径。
     - 状态管理：输入值、时区、粒度、格式、加载态、错误态、结果态、复制反馈。
     - 核心行为：触发请求、展示加载/成功/失败、一键复制、安全展示用户输入与错误消息。

   - `src/pages/ToolPage.jsx`：工具页路由承载层。
     - 通过 `IMPLEMENTED_TOOLS` 映射表，按 `toolId` 动态加载对应实现组件。
     - 使用 React `lazy` + `Suspense` 做代码分割；未实现工具回退到占位说明。

   - `src/index.css`：新增时间戳工具相关样式。
     - 复用现有设计令牌（`--accent`、`--surface`、`--border` 等）与明暗主题策略。
     - 包含表单、按钮、错误提示、结果框、复制 Toast 等样式，支持移动端布局。

2. **请求与响应协议**

   - **基址配置**：通过 `import.meta.env.VITE_API_BASE` 配置后端 API 基址；默认空字符串表示与前端同域。
   - **POST /api/timestamp/toDateTime**
     - 请求体：`timestamp`（数值）、`granularity`（`SECONDS`/`MILLISECONDS`）、`timezoneId`（必填 IANA）、`formatPattern`（可选）。
     - 成功 `data`：`formattedDateTime`、`timezoneId`、`formatPattern`、`year`、`month`、`day`、`hour`、`minute`、`second`。
   - **POST /api/timestamp/toTimestamp**
     - 请求体：`dateTimeString`（必填）、`timezoneId`、`formatPattern`（可选）、`granularity`（可选）。
     - 成功 `data`：`timestamp`（数值）、`granularity`、`originalDateTimeString`、`timezoneId`。
   - **错误包络**：业务失败时仍使用 `{ success: false, errorCode, errorMessage, data: null }`，可能伴随 HTTP 400。前端统一将该包络转为 `ApiError`。

3. **错误与安全处理**

   - 错误展示：捕获 `ApiError` 并在页面展示 `errorMessage`，必要时包含 `errorCode`。
   - 展示安全：用户输入与接口返回的错误文案通过 `escapeHtml()` 做文本化处理后再展示，避免不安全 HTML 注入。
   - 复制能力：优先使用 `navigator.clipboard.writeText`；失败时降级到 `document.execCommand('copy')`，并给出明确失败提示。

4. **默认与时区策略**

   - 时区默认 `Asia/Shanghai`，格式默认 `YYYY-mm-dd HH:mm:ss`，粒度默认 `SECONDS`。
   - 时区列表仅使用完整 IANA 标识（如 `Asia/Shanghai`、`America/New_York`），不推荐三字母缩写（如 `CST`）。

### 使用说明

1. **本地开发**

   - 运行：`pnpm dev`（或 `npm run dev`），默认 Vite 端口。
   - 访问首页 `/` 后点击「Unix 时间戳与时区转换」卡片，或直接访问 `/tools/001`。

2. **配置后端地址（CORS/基址）**

   - 若后端与前端不同域：
     - 在项目根目录创建 `.env.development` 并设置 `VITE_API_BASE=http://localhost:8080`（示例）。
     - 确保后端已配置允许前端来源的 CORS 策略，或使用 Vite 代理转发（可在 `vite.config.js` 中按需要补充 `proxy` 配置）。
   - 生产/验收环境：通过构建环境变量注入 `VITE_API_BASE`，保证前端能访问约定的 `/api/timestamp/*` 端点。

3. **页面交互**

   - 时间戳转日期时间：填入时间戳数值（支持秒/毫秒大数字），选择粒度、时区、输出格式，点击「转换为日期时间」。
   - 日期时间转时间戳：填入日期时间字符串（需与「解析格式」匹配），选择时区、解析格式、输出粒度，点击「转换为时间戳」。
   - 结果区点击「复制」可复制主结果（格式化日期时间或时间戳文本），右上角会出现成功/失败提示。

### 验证结果

1. **功能验证（需后端可用）**

   - **用例 1：时间戳 → 日期时间（UTC）**
     - 输入：`1609459200`，粒度：`SECONDS`，时区：`UTC`，格式：`YYYY-mm-dd HH:mm:ss`。
     - 预期成功：`data.formattedDateTime === "2021-01-01 00:00:00"`，且 `year/month/day/hour/minute/second` 分量与字符串一致。

   - **用例 2：日期时间 → 时间戳（UTC）**
     - 输入：`2021-01-01 00:00:00`，时区：`UTC`，解析格式：`YYYY-mm-dd HH:mm:ss`，粒度：`SECONDS`。
     - 预期成功：`data.timestamp === 1609459200`，与上一步原始输入一致。

   - **用例 3：错误路径（无效时区）**
     - 输入：`1609459200`，时区改为非法值（或下拉不存在值时可通过接口校验触发）。
     - 预期：页面展示接口返回的 `errorMessage`（可能伴随 `errorCode` 如 `INVALID_TIMEZONE`），不出现未捕获异常或空白错误。

   - **用例 4：复制功能**
     - 在成功结果区点击「复制」，预期出现 Toast 提示「已复制到剪贴板」。
     - 若浏览器 Clipboard API 被禁用，降级到 `execCommand` 时仍应复制成功；若两者均失败，应提示失败原因。

2. **环境与浏览器**

   - 已在以下环境确认结构可构建：
     - Node：按项目 `package.json`/`engines` 约定使用当前 LTS。
     - 包管理器：`pnpm`（推荐），或同等 `npm` 环境。
     - 主要目标浏览器：Chrome、Edge、Safari、Firefox（以 `browserslist`/Vite 默认目标为准）。

3. **构建与静态检查**

   - `pnpm lint`：已通过 ESLint 静态检查（以仓库当前配置为准）。
   - `pnpm build`：可正常产出 `dist/` 构建产物。

### 已知限制

1. 当前实现未接入批量接口 `/api/timestamp/batch/*`，页面 UI 也未包含批量输入/输出；后续若需要，可在 `timestampApi.js` 中扩展并新增页面面板。
2. 前端未提供独立的本地对照预览（如纯 JS 时间戳推算）。按约束仅允许后端结果作为权威展示；若后续增加本地辅助对照，需明确标注其非权威性质。
3. `formatPattern` 与 `granularity` 的具体合法枚举以运行中的后端接口校验为准；页面仅提供 TASK 文档中示例模式供选择。
4. 页面尚未持久化用户偏好（时区、格式、最近输入）到 `localStorage`；可与任务 054 配合实现。
