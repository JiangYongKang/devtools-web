### 文档背景

1. 本文档对应 TASK_003：XML 文档的缩进排版与空白压缩
2. 提供站内 XML 文本的可读缩进排版与空白压缩功能，支持格式化与压缩两种输出
3. 可选展示后端返回的文档结构摘要（根元素名、元素总数、最大深度、元素路径列表）
4. 核心处理经后端 REST 契约完成，前端负责选项组织、加载态、错误呈现、结果与安全复制

### 文档目标

1. 说明 XML 工具的前端实现方式、模块分工与数据流
2. 提供联调环境配置与验证步骤
3. 记录大文本、错误样例的验证步骤与预期结果

### 实现说明

#### 模块分工

1. **API 封装层** (`src/services/xmlApi.js`)
   - `formatXml`: 调用 POST `/api/xml/format` 进行 XML 格式化
   - `compressXml`: 调用 POST `/api/xml/compress` 进行 XML 压缩
   - `ApiError`: 自定义错误类，包含 errorCode、errorMessage、nodePath、lineNumber、columnNumber
   - 导出选项常量：缩进类型、缩进宽度、声明策略、注释策略

2. **页面组件** (`src/components/XmlTool.jsx`)
   - 多行 XML 输入区
   - 格式化选项：indentType、indentWidth、declarationPolicy、commentPolicy、includeStructure
   - 压缩选项：declarationPolicy、commentPolicy、includeStructure
   - 结果展示区（支持复制）
   - 文档结构摘要展示（可选）
   - 加载中、成功、失败状态区分

3. **路由注册** (`src/pages/ToolPage.jsx`)
   - 工具 ID '003' 懒加载 `XmlTool` 组件

#### 响应包络解析（与 JSON/Timestamp 接口的差异）

XML 接口的响应包络与其他工具不同：

```javascript
// 成功响应
{
  "success": true,
  "output": "<格式化或压缩后的 XML 字符串>",
  "structure": {  // 可选，仅当 includeStructure=true 时返回
    "rootElementName": "root",
    "totalElements": 10,
    "maxDepth": 3,
    "elementPaths": ["/root", "/root/child", ...]
  }
}

// 失败响应
{
  "success": false,
  "errorCode": "PARSE_FAILED",
  "errorMessage": "XML 解析失败...",
  "nodePath": "/root/item[2]",
  "lineNumber": 5,
  "columnNumber": 12
}
```

**关键差异**：
- JSON/Timestamp 接口使用 `data` 包络：`{ success: true, data: { ... } }`
- XML 接口直接使用顶层 `output` 和 `structure` 字段

#### XSS 安全策略

所有不可信输入均经过 `escapeHtml` 函数转义后再展示：
- 用户输入的 XML 文本
- 错误信息（errorMessage）
- 节点路径（nodePath）
- 结构路径列表（elementPaths）
- 复制状态提示消息

#### 错误码映射（与后端 DOC_003 对齐）

| 错误码 | 用户友好文案 | 常见触发场景 |
|--------|-------------|-------------|
| NULL_INPUT | 输入不能为空（XML 字符串缺失或为 null） | 请求体缺失、xmlString 为 null |
| EMPTY_INPUT | 输入不能为空字符串（仅空白字符） | 仅输入空白字符 |
| INVALID_INDENT | 缩进参数无效（类型需为 SPACE/TAB，宽度需为 1-8） | indentWidth 为 0 或 9、非法 indentType |
| PARSE_FAILED | XML 解析失败 | 非 XML 文本、标签未闭合、语法错误 |
| TRANSFORM_FAILED | XML 转换失败 | 转换过程中出错 |
| HTTP_ERROR | 网络请求失败 | 网络超时、服务不可用、CORS 问题 |
| UNKNOWN_ERROR | 未知错误 | 其他未预期错误 |

#### 请求取消机制

使用 `AbortController` 实现请求取消：
- 格式化作 `abortKey = 'format'`
- 压缩操作 `abortKey = 'compress'`
- 同一操作重复发起时，先取消前一个请求

### 使用说明

#### 页面入口

通过首页工具列表或直接访问路由 `/tools/003` 进入 XML 工具页面。

#### 格式化操作

1. 在「XML 输入」文本框中粘贴或输入 XML 文本
2. 选择格式化选项：
   - **缩进类型**：SPACE（空格）或 TAB（制表符）
   - **缩进宽度**：1-8（SPACE 时为每层空格数，TAB 时仅用于校验）
   - **声明策略**：
     - KEEP：保留原声明（若无则不添加）
     - REMOVE：移除声明
     - REWRITE：重写为标准 UTF-8 声明
   - **注释策略**：
     - KEEP：保留注释
     - REMOVE：移除注释
   - **请求文档结构摘要**：勾选后返回结构信息
3. 点击「格式化」按钮
4. 查看格式化结果，可点击「复制」按钮复制结果
5. 若勾选了结构摘要，查看根元素、元素总数、最大深度和路径列表

#### 压缩操作

1. 在「XML 输入」文本框中粘贴或输入 XML 文本
2. 选择压缩选项：
   - **声明策略**：同上
   - **注释策略**：同上
   - **请求文档结构摘要**：同上
3. 点击「压缩（紧凑单行）」按钮
4. 查看压缩结果，可点击「复制」按钮复制结果

#### API 基址配置

通过 `.env.development` 或构建时环境变量配置：
```
VITE_API_BASE=http://localhost:8080
```

若为空字符串，则使用相对路径请求（依赖反向代理）。

### 验证结果

#### 验证环境

- 开发环境：Vite + React
- 后端服务：devtools 后端（需运行在可访问地址）
- 浏览器：Chrome / Firefox / Edge 最新版本

#### 验证步骤

##### 1. 格式化功能验证

**样例输入**：
```xml
<?xml version="1.0" encoding="UTF-8"?><root><item id="1"><name>Test</name></item><item id="2"><name>Another</name></item></root>
```

**验证步骤**：
1. 粘贴上述 XML 到输入框
2. 保持默认选项（SPACE、宽度 2、KEEP 声明、KEEP 注释）
3. 点击「格式化」
4. **预期结果**：
   - 显示多行缩进格式化的 XML
   - 每个元素独占一行，有适当缩进
   - 声明被保留

##### 2. 压缩功能验证

**样例输入**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <item id="1">
    <name>Test</name>
  </item>
</root>
```

**验证步骤**：
1. 粘贴上述 XML 到输入框
2. 点击「压缩（紧凑单行）」
3. **预期结果**：
   - 输出为紧凑单行
   - 无多余空白（元素间空格、换行被移除）

##### 3. 结构信息验证

**样例输入**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<catalog>
  <book id="bk101">
    <author>Gambardella, Matthew</author>
    <title>XML Developer's Guide</title>
  </book>
  <book id="bk102">
    <author>Ralls, Kim</author>
    <title>Midnight Rain</title>
  </book>
</catalog>
```

**验证步骤**：
1. 粘贴上述 XML
2. 勾选「请求文档结构摘要」
3. 点击「格式化」或「压缩」
4. **预期结果**：
   - 显示结构信息区块
   - rootElementName: "catalog"
   - totalElements: 统计值（含 catalog、book、author、title 等）
   - maxDepth: 3（catalog -> book -> author）
   - elementPaths: 包含各元素的 XPath 风格路径

##### 4. 错误场景验证

**场景 A：非法缩进宽度**
- 输入任意合法 XML
- 在代码调试中临时修改 indentWidth 为 0 或 9（或通过 API 直接测试）
- **预期结果**：显示 `[INVALID_INDENT]` 错误码和对应错误信息

**场景 B：解析失败（标签未闭合）**

**样例输入**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<root>
  <item>
    <name>Test
  </item>
</root>
```

**验证步骤**：
1. 粘贴上述 XML（注意 `<name>` 标签未闭合）
2. 点击「格式化」
3. **预期结果**：
   - 显示 `[PARSE_FAILED]` 错误码
   - 显示具体错误信息
   - 显示节点路径（如 `/root/item` 或空）
   - 显示行号和列号（后端返回时）
   - 页面不崩溃

**场景 C：空输入**
- 输入框留空或仅输入空白字符
- 点击「格式化」
- **预期结果**：显示 `[EMPTY_INPUT]` 或 `[NULL_INPUT]` 错误（以后端返回为准）

##### 5. 复制功能验证

**验证步骤**：
1. 输入合法 XML 并格式化/压缩
2. 点击结果区的「复制」按钮
3. **预期结果**：
   - 显示「已复制到剪贴板」的成功提示
   - 剪贴板内容与显示结果一致

##### 6. 大文本场景验证

**样例准备**：
- 生成包含 1000+ 元素的 XML 文档（可通过脚本生成或使用测试数据）
- 确保文本体积 > 100KB

**验证步骤**：
1. 粘贴大文本到输入框
2. 点击「格式化」
3. **预期结果**：
   - 界面保持可滚动、可操作
   - 显示「格式化中...」加载状态
   - 完成后显示结果或错误提示
   - 无长时间假死（> 10 秒无响应）

#### 已知限制

1. **后端限制**：
   - 属性顺序可能与原文不完全一致（依赖后端解析器行为）
   - 空元素可能被转换为自闭合形式（如 `<item/>` 替代 `<item></item>`）
   - 实体引用可能被规范化（如 `&amp;` 可能被解析后重新序列化）

2. **前端限制**：
   - 极大文本（> 数 MB）可能影响页面性能，建议分段处理
   - 剪贴板 API 在某些浏览器中可能需要 HTTPS 环境
   - 复制功能降级依赖 `document.execCommand('copy')`（已弃用但仍广泛支持）

3. **安全限制**：
   - 所有用户输入均经 HTML 转义后展示，避免 XSS
   - 不直接渲染用户输入为 HTML
