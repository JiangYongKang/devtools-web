# DOC_005 - Base64 互转

## 概述

本工具提供 **纯前端** 的 Base64 与二进制数据互转功能，所有编解码操作均在浏览器本地执行，**不向任何后端服务器发送数据**。

## 访问地址

- 前端页面：`http://localhost:5173/tools/005`

## 技术实现

### 核心依赖

- `btoa()` / `atob()`：浏览器原生 Base64 编解码 API
- `TextEncoder` / `TextDecoder`：文本与字节序列转换
- `FileReader`：文件读取（ArrayBuffer 格式）
- `Blob` / `URL.createObjectURL()`：二进制数据下载

## 功能说明

### 1. Base64 编码

#### 输入方式

| 方式 | 说明 | 入口 |
|------|------|------|
| 文本输入 | 支持 UTF-8、GBK、GB2312、Big5、Shift-JIS 等编码 | 文本框输入 |
| 文件输入 | 支持任意类型文件 | 文件选择 / 拖拽 / 粘贴 |
| 粘贴文件 | 从剪贴板粘贴图片等文件 | 直接 `Ctrl+V` 到页面 |

#### 编码流程

```
文本/文件 → ArrayBuffer → Uint8Array → binary string → btoa() → Base64 字符串
```

### 2. Base64 解码

#### 输出格式

| 格式 | 说明 | 适用场景 |
|------|------|----------|
| 文本 | 按指定编码解码为字符串 | 文本数据 |
| 二进制（下载） | 保存为 .bin 文件 | 图片、压缩包等二进制文件 |

#### 解码流程

```
Base64 字符串 → 去除空白 → atob() → binary string → Uint8Array → ArrayBuffer
                                                              → 文本 (TextDecoder)
                                                              → 下载 (Blob)
```

## 性能策略与边界处理

### 大文件处理

**问题**：
- 浏览器主线程执行大文件编码可能导致页面卡顿
- `btoa()` 对超长字符串可能存在性能问题

**解决方案**：

1. **文件大小限制**：
   - 默认安全限制：`5 MB`
   - 超出时提示用户但不强制阻止

2. **分块处理**：
   - 块大小：`1 MB`
   - 分块转换后拼接
   - 处理间隔：每 50 块让出主线程（`setTimeout(0)`）

3. **关键代码**（Base64Tool.jsx:32-43）：

```javascript
const CHUNK_SIZE = 1024 * 1024
const YIELD_INTERVAL = 50

async function processInChunks(buffer, callback, chunkSize = CHUNK_SIZE) {
  const totalChunks = Math.ceil(buffer.byteLength / chunkSize)
  for (let i = 0; i < totalChunks; i++) {
    const start = i * chunkSize
    const end = Math.min(start + chunkSize, buffer.byteLength)
    const chunk = buffer.slice(start, end)
    callback(chunk, i)
    if (i % YIELD_INTERVAL === 0) {
      await new Promise((resolve) => setTimeout(resolve, 0))  // 让出主线程
    }
  }
}
```

### 二进制数据检测

**问题**：
- 解码二进制数据为文本时可能产生乱码或不可见字符
- 需要在 UI 上提示用户

**解决方案**：
- 解码后检查前 1024 字节是否包含 `NUL (0x00)`
- 检测到二进制特征时显示警告提示

### 输入验证

**Base64 格式验证**：
1. 仅包含合法字符：`A-Z`、`a-z`、`0-9`、`+`、`/`、`=`
2. 长度为 4 的倍数（padding）
3. 尝试 `atob()` 解码不报错

**关键代码**（Base64Tool.jsx:90-103）：

```javascript
function isValidBase64(str) {
  if (!str) return false
  const trimmed = str.trim()
  if (trimmed.length === 0) return false
  if (!/^[A-Za-z0-9+/=]*$/.test(trimmed.replace(/\s+/g, ''))) return false
  const clean = trimmed.replace(/\s+/g, '')
  if (clean.length % 4 !== 0) return false
  try {
    atob(clean)
    return true
  } catch {
    return false
  }
}
```

## XSS 防护

### 防护策略

1. **所有用户输入**：经 `escapeHtml()` 转义后展示
2. **所有错误信息**：经 `escapeHtml()` 转义后展示
3. **所有结果文本**：经 `escapeHtml()` 转义后展示
4. **不使用 `innerHTML` 直接渲染未转义内容**

### 转义实现

```javascript
function escapeHtml(text) {
  if (text == null) return ''
  const str = String(text)
  const div = document.createElement('div')
  div.textContent = str  // 利用 DOM 自动转义
  return div.innerHTML
}
```

## 降级策略

### 场景与处理

| 场景 | 策略 | 用户提示 |
|------|------|----------|
| 文件 > 5MB | 允许但提示风险 | 「文件过大，建议使用小于 5 MB 的文件」 |
| 解码检测到二进制 | 继续但显示警告 | 「检测到可能的二进制数据，建议选择『二进制（下载）』格式」 |
| TextEncoder 不支持 | 理论不发生（现代浏览器均支持） | - |
| 剪贴板 API 不支持 | 降级到 `document.execCommand('copy')` | - |

### 已知限制

1. **浏览器内存限制**：
   - 超大文件（> 50MB）可能导致内存不足
   - 建议分块处理或使用后端服务

2. **`atob()` / `btoa()` 限制**：
   - 仅支持 Latin-1 字符集的二进制字符串
   - Unicode 文本需先编码为 UTF-8 字节

3. **FileReader API**：
   - 仅在 HTTPS 或 localhost 下可用（浏览器策略）
