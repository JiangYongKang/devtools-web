# DOC_008 - 正则匹配验证

## 概述

本工具提供 **纯前端** 的正则表达式匹配验证功能，支持实时匹配、高亮展示、捕获组查看等。所有操作均在浏览器本地执行，**不向任何后端服务器发送数据**，可在离线或无后端环境下使用。

## 访问地址

- 前端页面：`http://localhost:5173/tools/008`

## 技术实现

### 核心依赖

| 依赖 | 用途 | 说明 |
|------|------|------|
| `RegExp` | 正则编译与匹配 | JavaScript 原生正则引擎 |

### 支持的修饰符（Flags）

### 状态指示

| 状态 | 显示 | 含义 |
|------|------|------|
| `等待输入` | 蓝色 | 未输入正则表达式或样本文本 |

## 关键实现细节

### 1. 页面与逻辑分离

**说明**：正则编译、匹配执行、结果加工等与 DOM 无关的逻辑独立在 `regexUtils.js` 中实现，主组件仅负责 UI 和状态管理。

**职责划分**：
- `regexUtils.js`：
  - `compileRegex()` - 正则编译
  - `executeRegexWithTimeout()` - 带超时保护的匹配执行
  - `buildHighlightedHtml()` - 构建高亮 HTML
  - `validateInputs()` - 输入验证与警告生成
  - `formatMatchInfo()` - 匹配信息格式化
- `RegexTool.jsx`：
  - 输入表单与状态管理
  - 防抖逻辑
  - 结果渲染

### 2. 超时保护

**说明**：正则表达式的「灾难性回溯」问题可能导致匹配操作无限执行，造成浏览器卡死。通过 `setTimeout` 实现超时保护，超过阈值后抛出错误。

**关键代码**（regexUtils.js:39-102）：

```javascript
function executeRegexWithTimeout(regex, text) {
  return new Promise((resolve, reject) => {
    let hasTimedOut = false
    const timeoutId = setTimeout(() => {
      hasTimedOut = true
      reject(new Error(`匹配超时（超过 ${EXECUTION_TIMEOUT_MS}ms），可能是复杂表达式或回溯导致`))
    }, EXECUTION_TIMEOUT_MS)

    try {
      // 匹配逻辑...
      while (!hasTimedOut) {
        const match = workingRegex.exec(text)
        if (!match) break
        // 收集匹配...
      }
      clearTimeout(timeoutId)
      resolve({ matches, matchCount, hasMoreMatches: matchCount > MAX_MATCH_COUNT })
    } catch (err) {
      clearTimeout(timeoutId)
      reject(err)
    }
  })
}
```

**注意事项**：
- JavaScript 是单线程的，超时检查在匹配循环中通过 `hasTimedOut` 标志实现
- 超时阈值：2000ms（`EXECUTION_TIMEOUT_MS`）
- 超时后不会强行终止执行，但会在下一次循环检测时退出并 reject

### 3. 防抖机制

**说明**：用户输入时会频繁触发匹配，通过防抖延迟执行，避免不必要的计算开销。

**关键代码**（RegexTool.jsx:136-157）：

```javascript
useEffect(() => {
  if (debounceTimerRef.current) {
    clearTimeout(debounceTimerRef.current)
  }
  // ...
  debounceTimerRef.current = setTimeout(() => {
    executeMatch()
  }, DEBOUNCE_DELAY_MS)
  return () => {
    if (debounceTimerRef.current) {
      clearTimeout(debounceTimerRef.current)
    }
  }
}, [pattern, text, selectedFlags, executeMatch])
```

**说明**：
- 防抖延迟：300ms（`DEBOUNCE_DELAY_MS`）
- 用户停止输入 300ms 后才执行匹配
- 组件卸载时清理定时器

### 4. 匹配数量限制

**说明**：过多的匹配项会导致 DOM 渲染卡顿，限制展示数量但统计实际匹配数。

**关键代码**（regexUtils.js:76-84）：

```javascript
if (matches.length < MAX_MATCH_COUNT) {
  matches.push({
    index: match.index,
    match: match[0],
    groups: match.slice(1),
    namedGroups: match.groups || {},
    length: match[0].length,
  })
}
matchCount++
```

**说明**：
- 最多展示 500 个匹配项（`MAX_MATCH_COUNT`）
- 超过限制时仍统计实际匹配总数
- UI 中明确提示「匹配项超过 500 个，仅显示前 500 个」

### 5. 空匹配死循环防护

**说明**：某些正则（如 `a*`）可能产生零长度匹配，导致 `exec` 无限循环。检测零长度匹配并手动推进 `lastIndex`。

**关键代码**（regexUtils.js:88-92）：

```javascript
if (match[0].length === 0) {
  workingRegex.lastIndex = match.index + 1
  if (workingRegex.lastIndex === lastIndex) break
  lastIndex = workingRegex.lastIndex
}
```

## 安全说明

### XSS 防护策略

1. **所有用户输入**：经 `escapeHtml()` 转义后展示
2. **所有错误信息**：经 `escapeHtml()` 转义后展示
3. **所有匹配结果**：经 `escapeHtml()` 转义后展示
4. **高亮 HTML 构建**：先转义纯文本，再插入 `<mark>` 标签

### 转义实现

```javascript
function escapeHtml(text) {
  if (text == null) return ''
  const str = String(text)
  const div = document.createElement('div')
  div.textContent = str  // 利用 DOM 自动转义
  return div.innerHTML
}
```

### 高亮 HTML 构建流程

```
原始文本 → 转义为安全 HTML → 插入 <mark class="match-highlight"> 标签 → 最终安全 HTML
```

**关键代码**（regexUtils.js:104-148）：

```javascript
function buildHighlightedHtml(text, matches) {
  // ... 合并重叠区间 ...
  const parts = []
  let pos = 0

  for (const m of mergedMatches) {
    if (m.start > pos) {
      parts.push(escapeHtml(text.slice(pos, m.start)))  // 非匹配部分先转义
    }
    parts.push(`<mark class="match-highlight">${escapeHtml(text.slice(m.start, m.end))}</mark>`)  // 匹配部分先转义再包装
    pos = m.end
  }

  if (pos < text.length) {
    parts.push(escapeHtml(text.slice(pos)))
  }

  return parts.join('')
}
```

## 性能与限制

### 输入限制

| 限制项 | 阈值 | 说明 |
|--------|------|------|
| 正则表达式长度 | 1000 字符 | 超过会直接报错 |
| 正则表达式长度（警告） | 700 字符 | 超过发出性能警告 |
| 样本文本长度（警告） | 100,000 字符 | 超过发出性能警告 |
| 匹配超时 | 2000ms | 超过中止并报错 |
| 匹配详情展示数 | 500 | 超过仅统计不展示 |

### 回溯风险检测

**检测规则**：检测在量词后使用环视的模式：
- `(?=.*)` - 正向前瞻 + 贪婪量词
- `(?!.*)` - 负向前瞻 + 贪婪量词
- `(?<=.*)` - 正向后顾 + 贪婪量词
- `(?<!.*)` - 负向后顾 + 贪婪量词

**用户提示**：「检测到可能的回溯风险模式，建议避免在量词后使用复杂的环视结构」

### 1. 基础匹配验证

1. 打开页面 `http://localhost:5173/tools/008`
2. 在表达式框输入：`\d+`
3. 在样本文本框输入：`abc123def456`
4. **预期结果**：
   - 状态显示「匹配成功」（绿色）
   - 高亮预览显示 `123` 和 `456` 被高亮
   - 匹配详情显示 2 个匹配项
   - 第 1 个匹配：位置 3-6，文本 `123`
   - 第 2 个匹配：位置 9-12，文本 `456`

### 2. 语法错误验证

1. 在表达式框输入：`[a-z`（缺少右括号）
2. **预期结果**：
   - 状态显示「编译错误」（红色）
   - 错误框显示具体语法错误信息

### 3. 无匹配验证

1. 在表达式框输入：`xyz`
2. 在样本文本框输入：`abc123`
3. **预期结果**：
   - 状态显示「无匹配」（橙色）
   - 显示「表达式在样本文本中未找到匹配」

### 4. 快速示例验证

1. 点击「邮箱」按钮
2. **预期结果**：
   - 表达式自动填充为邮箱正则
   - 样本文本自动填充示例文本
   - 匹配成功，高亮显示 2 个邮箱

### 5. 修饰符验证（忽略大小写）

1. 表达式：`hello`

   - 预期：匹配 3 个（`Hello`、`HELLO`、`hElLo`）

### 6. 捕获组验证

1. 表达式：`(\d{4})-(\d{2})-(\d{2})`

   - 捕获组 `$1` = `2024`
   - 捕获组 `$2` = `01`

### 7. 防抖验证

1. 快速连续输入表达式字符
2. **预期结果**：
   - 停止输入后才执行匹配
   - 不会频繁触发状态变更

### 8. 网络隔离验证

1. 断开网络连接
2. 打开页面并执行匹配
3. **预期结果**：功能正常，无网络请求

### 9. XSS 验证

1. 在样本文本中输入：`<script>alert('xss')</script>`

   - 无后端依赖
   - 无网络请求
