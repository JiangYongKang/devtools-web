### 文档目的

本文件是前端在编码、测试、文档与任务管理上的总入口：说明目录分工、TASK/DOC 约定、验收口径，并维护任务列表与状态。

交付物含两类（工具界面 / 站内可复用的组件与逻辑），均须有成对的 `features/TASK_XXX.md` 与 `docs/DOC_XXX.md`；是否走后端网络以对应 TASK 为准。实现上每项是独立功能单元；需要后端时用统一客户端出口，浏览器可本地完成的应保持可离线、弱依赖。

工程要求：可维护、可验证；文案与交互与站内一致；TASK 要写清要什么，DOC 写实现与验证；实现细节不写进 FEATURE 任务长文。

### 架构要点

功能独立；是否注册路由不改变核心交互边界。需 API 时不要复制两套业务逻辑；变更契约优先改封装层。样式尽量作用域在本任务内，避免改全局导致其它工具页回归；确需动全局时 TASK 写明影响并在验收抽检关联页。

### 目录约定

| 路径                 | 用途                                     |
| -------------------- | ---------------------------------------- |
| features/FEATURE.md  | 本规范与任务索引（本文件）               |
| features/TASK_XXX.md | 单项需求与验收，三位编号与列表一致       |
| docs/DOC_XXX.md      | 与 TASK 同号的实现说明、用法、验证、限制 |

### 任务文档（TASK_XXX.md）

- 编号与 FEATURE 列表一一对应。
- 以可验收结果为主；不写死具体组件或 Hook 名。可约定实现所在目录，其下文件与分层由研发自定。
- 宜简洁列举。若某任务禁止发后端请求，须在任务要求或约束中写明。

**TASK 骨架**：任务目标 → 任务要求 → 任务约束 →（可选）实现位置 → 交付产物 → 注释规范 → 验收标准。

### 功能文档（DOC_XXX.md）

与 TASK 同号。建议含：文档背景、文档目标、实现说明、使用说明、验证结果、已知限制。

### 编码与测试（全局）

- 与仓库技术栈（Vite、React 等）及目录习惯一致，改动范围最小化。
- 注释：非显而易见处用简洁中文；用户可见错误要清晰。用户内容须安全展示，避免不安全 HTML 注入。
- 构建、Node 版本、浏览器目标以 `package.json`、Vite 与团队约定为准；依赖较新 Web API 时在 TASK/DOC 写兼容与降级。
- 测试：以 `package.json` 脚本为准；覆盖点与是否必测以 TASK 为准。依赖浏览器、网络或后端的在 DOC 写手动验证。纯逻辑尽量可测；用例名表达意图，避免脆弱实现细节耦合。
