### 文档目的
本文件定义前端任务与文档的统一规范，约束任务拆分、目录边界、测试范围与交付格式，确保不同研发按同一标准落地。

### 命名与配对规则
- 任务文件必须按 `TASK_XXX.md` 创建，`XXX` 为三位数字，按顺序递增。
- 文档文件必须按 `DOC_XXX.md` 创建，`XXX` 必须与对应任务编号一致。
- 每个任务必须同时存在 `features/TASK_XXX.md` 与 `docs/DOC_XXX.md`，禁止只建其一。

### TASK 编写硬性规范
- `TASK_XXX.md` 必须保持简洁，只使用简短段落与列表，不要空行。
- `TASK_XXX.md` 的「任务目标」必须以 3～5 条功能描述落成（每一条对应一块独立、可验收的能力边界），禁止使用「仅以工具名一言蔽之」或「固定三套话」来代替多条功能叙述；不推荐再套用「第一项、第二项、第三项」式模板化三点写法，仅以条数与语义覆盖为准。
- 「任务目标」须围绕同一核心场景 **尽量想全**同类工具常见的延伸能力并结合本任务写明（可按领域替换，如 JSON：格式化与紧凑、转义与去转义、搜索与高亮、键排序、JSONPath 查找与定位、文档内增删改键值、复制与下载、大文本与性能、校验与错误定位至行列、与剪贴板或文件的衔接等——仅示例）；**凡出现在「任务目标」中的能力均需在本任务交付中实现**，不在同一 TASK 内用「可选」「本期不做」「后续再做」等表述搁置已写明的功能；若预估体量过大，应在立项时 **拆分多个 `TASK_XXX.md` 编号**分别承载，而不是在同一 TASK 中空列功能却不实现。
- `TASK_XXX.md` 只能描述实现文件夹范围，不限制具体组件、Hook、函数命名与代码组织细节。
- `TASK_XXX.md` 必须明确本任务的页面文件夹、测试文件夹、纯逻辑函数文件夹。
- 涉及工具输入与输出的任务必须提供「示例」交互（如示例按钮），支持一键填充可运行样例，便于用户快速理解工具使用方式。
- `TASK_XXX.md` 必须声明任务边界：当前任务不可读取、不可修改其他任务编号目录下的文件。

### 实现目录约束（所有任务必须遵守）
- 虽然任务文件按编号命名（`TASK_XXX.md` / `DOC_XXX.md`），但代码目录命名必须语义化（如 `js-format-compress`、`cron-explain`），禁止仅使用 `task011`、`task012` 这类纯编号目录名。
- 页面渲染相关代码放在当前任务的页面目录中，仅承担视图与交互编排职责。
- 与页面渲染无关的纯 JS 函数必须拆到独立文件，放在当前任务的逻辑目录中，禁止在 JSX 中堆叠大段逻辑函数。
- 单元测试放在当前任务的测试目录中，只覆盖纯 JS 函数，不要求覆盖 API 请求行为。
- 若任务需要 API，只在 TASK 中说明接口用途、入参/出参约定与错误处理要求，不在 TASK 中绑定具体实现组件名。

### 注释与质量要求
- 每一个方法都必须添加中文注释，说明方法目的、关键参数或返回语义。
- 代码改动必须控制在当前任务声明的目录范围内，避免跨任务耦合。
- 文档描述以可验收结果为导向，避免实现细节绑死研发方案。

### TASK 推荐模板（无空行）
- 任务目标：写 3～5 条功能（同一段落内连续表述、不出现空行；可在段内用分号分隔各条能力，也可用短横线列表项但条目之间不写空行）；其中须包含：核心主路径（用户首要完成的一件事）；围绕核心的多条延伸能力，按领域穷尽同类场景常见维度（仍以 JSON 为例：转义与去转义、搜索与高亮、键排序、JSONPath、增删改键值、格式化选项、校验与错位提示、diff、复制下载、大体量行为的策略或限制说明等）；上手与可操作（如示例一键填充、关键说明）；健壮与边界（非法输入、报错、浏览器能力不支持、大体量与安全展示等）；有外部 API 时须单列对接与异常（契约、超时、权限、HTTP 或空响应等）。条目总数仍控制在 3～5：可将相近能力合并为一条内的分号子句，但不要借合并删减已构思的能力；凡写入 TASK「任务目标」者须全部交付实现。
- 实现范围：页面文件夹、逻辑函数文件夹、测试文件夹。
- API 信息（可选）：接口列表、请求方式、主要参数、返回字段、错误约定。
- 任务约束：不得访问或修改其他任务目录，不限制具体组件命名。
- 验收标准：对「任务目标」中每一条功能均能逐条核对；写清页面行为、纯 JS 函数行为、测试通过标准；凡任务目标中出现的功能不得在验收中单列豁免（若需减量须回到任务拆分，另起编号）。

### DOC 推荐模板
- 背景与目标：为什么做、解决什么问题。
- 实现说明：目录落点、关键流程、边界处理。
- 测试与验证：纯 JS 单测结果、页面手工验证结果。
- 已知限制：当前 TASK 范式下仍存在的产品或环境级限制（与本工具实现无关的外部依赖、合规红线等）；不得用语义上等同于「任务目标已写但未实现」的已知限制来解释缺项，该类情况应在拆分 TASK 时在各自 `TASK_XXX.md` 中写全目标并实现。
